# 装饰商务逐页设计计划

用于 create 的装饰商务设计；参考 [设计指南](../references/decorative-business-design.md)。
本文件是填写提纲，不是可直接提交的 task.json，也不替代 content、scene 和独立审核。

## 整册约束

- 受众、场景与页数依据：
- 核心叙事与内容来源；示例数据/未知项标记：
- 原创/参考改编/忠实重建边界；采用的机制与独立设计决定：
- 设计母题；字体层级；颜色角色；折痕、边距、连接与图片规则：
- 色彩关系与视觉语言依据：当前品牌/参考的优先级；背景与主体、主辅色与强调、字图尺度、线重和节奏；无参考时的任务依据：
- 稳定项：正文标题域/章节导航、类型与字级、内容边界、金额/增速基线、线宽等级、来源与页码规则：
- 变化项：各页主体信息关系、重心、分支、阅读路径与图文比例；用户对逐页差异的要求：
- 角色例外：封面、章节、资料索引等为何使用不同标题域；不能仅为求变化移动正文标题：
- 原生可编辑内容与允许的独立图片：
- 代表页及其用途：目标达成 / 时间线 / 问题改进 / 成果图文 / 风险或计划（按实际内容选择）
- `design.review_profile`：`decorative_business`

## 叙事与页序（先于固定页数）

- 是否需要独立目录、章节首页、总结、决策、结束与备查资料；省略哪些，为什么：
- 章节名称、实际起止页；目录和导航如何随增删页更新：
- 总结表达什么判断；决策页请求什么；真正结束页承担什么功能：
- 附录在正文收束前还是标明位于结束后；是否要求感谢页必须为最后一页：
- 源内容ID → 当前页序映射；实际播放/PDF顺序与跨页引用复核：

这些是规划备注，不是新增task.json字段。不要把章节数量、页数或结束顺序机械套用到短简报。

## 逐页填写（映射到 design.pages[].composition）

- 页 ID：
- `page_role`：cover / contents / section / body / closing
- 观众问题与本页核心信息：
- `claim_content_id`：本页已有内容 ID；body 必填
- `content_relation`：
- `layout_family`：按实际空间关系命名，不按图标或配色命名
- `reading_path`：按阅读顺序填写本页已有内容 ID
- `information_attachment`：inside_structure / along_path / paired_with_visual / mixed
- `layer_plan.primary`：结论与主结构如何呈现
- `layer_plan.secondary`：证据、分组、题签与连接如何承载内容
- `layer_plan.detail`：编号、单位、时间、短说明与来源如何安放
- `rationale`：构图如何表达内容；与相邻页面保持或改变什么，为什么
- 稳定项对照（规划备注）：是否沿用共同标题域、字级与图形重量；若例外，理由是什么
- 本页视觉焦点与强调；图形如何承载正文关系；局部限定依附哪项证据，是否误加了重复底带（规划备注）：
- 实现备注（不直接加入 composition）：非矩形文字安全区、精确数据图表、图片用途、未知项

## 合并与审核记录

- 作者交付：页面范围、内容 ID、来源版本/构建 ID、实际候选预览、未解决问题。
- 合并检查：预览对应合入版本；页面不是换图标但保持同一拓扑；必要系列页仍可比较且符合用户要求。
- 版本对照：改善了什么、退化了什么、保留什么；疑似碰撞回到实际单页/局部确认。
- 色彩/视觉对标（如用户指定）：相应页面与总览的强调、背景对比、字图尺度、装饰承载和节奏；记录退步，不把色系变成通用偏好或禁用项。
- 逐页检查：主结论、数据口径、中文字体、说明归属、非矩形安全区、对比度与编辑能力。
- 独立整册 `deck_composition`：`status` 初始为 `revise`；`observations` 分别记录构图多样性、全册规整度、叙事完整性、色彩与视觉语言的证据；填写真实 `reviewed_page_ids`。必需视觉目标未达成时不因技术检查通过而批准。
- 对象覆盖：实际核对全部带 `content_id` 的节点后填写 `observed_node_ids`，包含页码、来源、脚注、图表、表格；不预填未经查看的节点。
- 最终以实际 PPTX 渲染和目标软件编辑验证为准；不以对象数、空白率或构图种类计审美分。
