# PPT Smith v4.1.0 Beta 1 Release Notes

PPT Smith v4.1.0 Beta 1 changes the product from a generic presentation
compiler into a model-directed authoring system with three isolated routes.
The Beta label is deliberate: the engine can enforce trustworthy delivery, but
the Bespoke and Template quality ceiling still depends on a capable model and
run-specific visual review.

## Routes

### Bespoke

The model owns source understanding, narrative, page geometry, native charts,
diagrams, speaker notes, and visual revision from a blank presentation. The
engine supplies source-bound execution, structural QA, real rendering, and a
hash-bound visual approval state.

### Template

The model analyzes the source and a user PPTX, then plans complete pages from a
reviewed Component Atlas. It reuses every feasible native component, combines
multiple components where needed, and may create a style-derived native
component only when the Atlas cannot express the content.

Template Beta adds:

- model-directed content and component intent;
- whole-page composition contracts and semantic page archetypes;
- source evidence, chart-data, speaker-note, and visible-binding gates;
- component content/decoration bounds, background policy, and responsive fit;
- rendered layout fingerprints and series rhythm checks;
- placeholder, duplicate-page-number, minimum-font, external-asset, and visual
  approval gates;
- explicit distinction between native template reuse and style-derived work.

### Standard / Engineering

The deterministic v3-compatible compiler remains available for smoke tests,
schema checks, diagnostics, and compatibility workflows. It is not presented
as a substitute for model-authored Bespoke or Template final output.

## Release engineering

- Version and public identity are sourced from `VERSION` and
  `packaging/identity.json`.
- Python runtime dependencies are pinned in `requirements.txt`.
- PptxGenJS and JSZip remain pinned by the runtime lockfile.
- GitHub Actions performs identity, Skill, test, and public-bundle checks.
- Private commercial PMO assets and local run artifacts are outside the public
  release tree and registry package.
- The public license is Apache-2.0.

## Compatibility

- Installed route: `article-html-to-ppt`
- Public slug: `meowclaw-pptsmith`
- Compatibility alias: `meowclaw-decksmith`
- Python: 3.9 or newer
- Verified renderer for this Beta: LibreOffice 26.2.4.2 on macOS
- PptxGenJS runtime: 4.0.1

## Honest limitations

- Bespoke and Template require a capable model; weak extractive output cannot
  be promoted to final.
- A first physical render is not guaranteed to be visually final. Font
  substitution, chart-label placement, and Office layout behavior still
  require rendered inspection.
- Real Microsoft PowerPoint and Keynote pixel parity is not claimed.
- Cross-template unit matrices do not prove every real-world PPTX object type.
  Encrypted, damaged, macro/OLE-heavy, or non-decomposable templates may be
  rejected.
- Final status remains run-specific and requires the route's complete QA and
  visual-review contract.

## Upgrade notes

Existing v3 compatibility commands remain available. V4 final authoring should
choose one route and must not mix Bespoke, Template, and Standard delivery
states in a single run. See `SKILL.md`, `docs/v4-three-route-architecture.md`,
`docs/v4-bespoke-architecture-plan.md`, and `docs/v4-template-route.md`.
