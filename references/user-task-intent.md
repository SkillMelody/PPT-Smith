# User task and content boundaries

Read when the task involves approved material, assistance with analysis, mixed content permissions, or a scoped revision. Use the request and existing files, not a mandatory intake questionnaire.

## Understand the work situation

Identify the audience, occasion, available material, expected deliverable and meaningful constraints. A person preparing a client review may need a different result from a person turning the same material into training. Business analysis is one possible content type, not the default workflow for every user. Language and geography do not prescribe density, title style or decoration.

Record only relevant decisions in the existing brief, content lock or notes. Do not add a new task schema or ask the user to choose internal modes. Infer routine design choices and continue; ask about missing facts or conflicting instructions only when they materially affect the result.

## Interpret allowed changes

| Request | Authoring behavior |
| --- | --- |
| Make a deck from supplied material | Select, summarize and organize for the stated purpose while preserving meaning and evidence. Supplying a file does not freeze every sentence. |
| Keep these approved titles, sentences, figures or page order | Preserve the specified parts. Use design freedom within that boundary; review status alone does not mean every other part is frozen. |
| Help analyze, explain or recommend | Derive supported findings and label uncertainty. Separate observed facts, calculations, hypotheses and proposed actions; do not invent causes, owners or targets. |
| Change only these pages or objects | Use the saved PPT Smith task where available. Identify related content that might become inconsistent, preserve everything outside the authorized scope, and report material conflicts before expanding the edit. |

Permissions may differ by section: a user can lock an executive summary and permit analysis elsewhere. Permission to improve layout does not authorize rewriting protected copy; permission to rewrite copy does not authorize changing approved data or silently abandoning a required template.

When summarizing or calculating, preserve the source's population, timeframe, units and denominator in visible labels as well as notes. A finding about one cohort cannot silently become a claim about all activity. This applies even when rewriting and analysis are allowed.

When the user asks to retain exact copy, compare titles, sentences, numbers and qualifiers against the source. Allow only requested presentational changes such as line breaks. Do not shorten protected sentences, add a conclusion or move required slide-visible content solely into speaker notes to make the page fit. Try an authorized layout adjustment first; explain the concrete conflict if the content still cannot fit the required page budget and readability.

## Keep design active

Choose page compositions from the content relationship: progression, comparison, hierarchy, scope, evidence or decision. Preserving copy still allows professional typography, spacing and graphical organization where authorized. Do not reduce faithful production to repetitive text boxes, and do not create unsupported claims merely to make each page look different.

Choose titles for the page's actual role. A finding can use a supported takeaway; a process, definition, setup or teaching page can use a topic or instructional title. Preserve titles explicitly fixed by the user. Plan navigation and an ending only as appropriate to the task and page budget; a short fixed-page handout does not need added cover, contents, chapter or thanks pages.

## Use existing route contracts honestly

- For create/recreate, put the scope in `design.brief` and retain source anchors in content and notes. A decorative composition's `claim_content_id` refers to its existing core message or title; it does not require inventing an assertion.
- Content Lock is the content baseline for the build. It does not mean the user forbids all future changes, and generating a new baseline cannot release a user-imposed restriction.
- V4 `title` and `message` are separate fields. Keep their required bindings and evidence; technical `assertion` terminology is not permission to rewrite an approved title or add an unsupported visible claim.
- Template final delivery retains its current message, density, role and visible-content checks. Bespoke retains its own narrative and visible-binding contracts. Fixed copy can conflict with these requirements. Report the concrete route restriction and available choices; do not add filler, hide required bindings in notes, misclassify a content page or lower a gate.
- Scoped updates operate on saved PPT Smith tasks. A third-party PPTX is not automatically an equivalent editable task; inspect the available structure and choose an existing supported route without promising lossless arbitrary-file editing.

## Review the user's result

Check content fidelity, useful expression and whole-deck coherence together. A content-preserving deck can still fail visual review; a polished deck can still fail the user's content restrictions. Recheck affected evidence and the assembled candidate after changes, using the selected route's actual review and edit/save/reopen requirements.

For a revision, distinguish a real contradiction from statements about different dates or scopes. Preserve a historical statement when a later update does not invalidate it. If the requested edit creates a genuine contradiction outside its allowed scope, identify the affected statements and seek only the consequential scope decision. Do not silently rewrite the rest of the deck.

Record observed behavior and limitations. These instructions guide the author; they do not constitute a new automatic approval detector, business analysis engine or universal content-lock enforcement mechanism.
